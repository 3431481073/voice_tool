# 运行时行为日志

> 按 `D:\MyProject\CLAUDE.md` §1 的 `runtime-log` 一份：**运行时的行为日志，可关**。
>
> **这份文件记录【可观测的运行时行为】—— 启动做什么、各状态耗时多久、什么时候释放资源。**
> **机器可读的运行日志在 `logs\voice_ball.log`**（见 [OUTPUT-SLOT.md](OUTPUT-SLOT.md) 第 4 项）。
> **本文只记"它运行时长什么样"，不记"我改了什么"** —— 后者在 [log.md](log.md)。
>
> **可关**：本文件可以停更（删掉不影响程序）。**程序不读它。**

## 一、启动序列（实测 2026-10-09）

顺序是固定的，日志里按时间排：

| # | 动作 | 实测耗时 | 日志行 |
| --- | --- | --- | --- |
| 1 | 建 `QApplication` | < 0.1s | —— |
| 2 | **单实例判定** | ~0.02s | `已持有单实例锁` / `已有实例在运行，本次启动直接退出` |
| 3 | 起 `FloatingBall`（球出现） | ~0.1s | —— |
| 4 | **起 `_warm_mic` 线程**（探测麦克风通路） | **1.1 ~ 1.6s** | `选中采集通路：麦克风阵列 (Realtek(R) Audio) @ MME 采样率=16000 通道=1 ...` |
| 5 | **注册全局热键** | ~0.01s | `全局快捷键已注册：<ctrl>+<alt>+<space>` |
| 6 | 起热键看门狗 | 立即（之后每 0.3s 一次） | `热键状态看门狗已启动（每 0.3s 对账一次）` |
| 7 | **模型** | 🔴 **不加载** | `启动时不加载模型，首次录音时与收音并行加载，闲置 300 秒后自动释放` |

> 🔴 **第 7 条是 2026-10-04 起的行为**：启动**不**占用显存（省约 1.9 GB 给别的程序，比如 ComfyUI）。
> **此前是"启动即加载、常驻不释放"。**

**→ 从进程起来到"能点、能按热键"约 1.6 秒。球不会转圈等待。**

## 二、一次完整录音的状态流转

```
idle ──(点击/热键)──> recording ──(再点一次)──> transcribing ──> idle
                                       │
                                       └─(界面立刻切走，尾音仍在后台收)
```

| 阶段 | 实测耗时 | 说明 |
| --- | --- | --- |
| `idle` → `recording` | ~0.01s | **界面立刻响应**；若模型不在内存，**同时**后台起加载 |
| 打开并验证采集通路 | **~1.0s** | 含跳过约 400ms 零填充 |
| **模型加载（仅当不在内存）** | **3.8s**（turbo）· 3.2~4.0s（medium） | **与用户说话并行**，通常被藏掉 |
| `recording` → `transcribing` | **~0.01s** | 🔴 **点停止后界面立刻切**，不等尾音 |
| **尾音收取（后台）** | **0.6s** | 实测 697 / 710 / 697 ms。**驱动缓冲里已录到但没交出来的尾音** |
| 转写 | **0.4 ~ 1.6s**（turbo）· 0.6 ~ 8.0s（medium） | 随音频长度变化 |
| `transcribing` → `idle` | ~0.01s | 同时开始 300 秒闲置倒计时 |

> **设计要点**：**"跟手"靠的是把尾音收取和模型加载都放到界面之外** ——
> 用户按下停止的那一瞬间界面就变了，剩下的都在后台。

## 三、资源占用（实测）

| 项 | 值 | 备注 |
| --- | --- | --- |
| **显存：模型驻留时** | **+1,981 MB**（medium）· **+2,095 MB**（turbo） | 实测 `nvidia-smi` 前后差值 |
| **显存：释放后残留** | **+93 ~ 125 MB** | CUDA 上下文，不可避免 |
| **释放耗时** | **0.03 ~ 0.05s** | 丢引用 + `gc.collect()` |
| **闲置释放延迟** | **300s**（= `IDLE_UNLOAD_S`） | 每次录音重置倒计时 |
| 内存（工作集） | ~107 MB | 进程常驻 |
| CPU | 空闲时≈0；录音时一个线程读 16 kHz 单声道 | 可忽略 |

**释放/不释放的取舍**：

| | 启动时加载（旧） | 按需加载 + 闲置释放（现在） |
| --- | --- | --- |
| 常驻显存 | **1.9 GB 一直占** | **0**（闲置 5 分钟后） |
| 首次录音等待 | 无 | 若录音短于 3.8s 需等一会儿；长于则无感 |

## 四、麦克风通路选择（运行时最活跃的一块）

**逐条探测，取第一条真正有音频的**。实测本机：

| 通路 | 结果 |
| --- | --- |
| **MME / 16000 / 单声道** | ✅ **平时选中**（探测 ~1.1s） |
| WASAPI / 单声道 | ❌ 吐高频垃圾（过零比 0.178 vs 正常 0.084） |
| WASAPI / 立体声 | 🟠 可用但不稳（频谱在 715~1949 Hz 间跳） |
| DirectSound | ❌ 返回速度远超实时，不是真采集 |
| WDM-KS | ❌ 打不开 |

**死路判据只用电平类**（峰值 / 标准差 / 直流）：
数字静音 = 峰值 1 / 标准差 0.5；畸形缓冲区 = 均值 +19274。

> 🔴 **频谱类判据（谱质心、过零率）只写日志、不做门禁。**
> 曾用它拦"WASAPI 单声道垃圾"，**但环境噪声下极不稳定**（同一条通路两测 0.213 / 0.098），
> **把好通路误判成死路、直接"没有可用通路"**。**宁可放进一条平庸通路，也不用会抖的指标否决通路。**

## 五、热键

**默认 `<ctrl>+<alt>+<space>`**，可在 `config.json` 改。

**运行时有一个看门狗，每 0.3 秒对账一次按键状态：**

| 时刻 | 日志 |
| --- | --- |
| 启动 | `热键状态看门狗已启动（每 0.3s 对账一次）` |
| **抓到残留** | `热键状态对账：清理残留按键 Key.ctrl（物理上并未按下）` |

> 🔴 **为什么需要它**：pynput 的 `HotKey` 用**长期存活**的 `_state` 集合，**只在收到 release 时才移除键**。
> 低级键盘钩子一旦漏事件（回调超时被系统摘钩、UAC/锁屏丢事件、程序在按键按着时重启），
> 那个键**永远留在里面** → 之后**少按一个键也能凑齐集合而误触发**（实测"只按 Ctrl+Alt 就启动"）。
>
> **踩过的坑**：一开始在【触发时】回查物理按键 —— 方向错了，
> pynput 是"钩子收事件 → 队列 → 再回调"，快速敲击时回调跑到时键已松开，
> **把正常按键也挡掉了**（"要点很多很多次"）。
> **现在改成后台对账，完全不碰触发路径。**

## 六、单调实例

**第二次启动的行为（实测）**：

```
语音悬浮球启动 (PID 58596)
已有实例在运行，本次启动直接退出        ← 本进程退出，不建窗口、不加载模型、不注册热键
收到第二次启动请求：b'show'             ← 已有实例把球拉到前台
```

**进程数保持 2 个**（= 1 个实例：venv launcher + 基础解释器）。

> **机制**：`QLocalServer` / `QLocalSocket`，命名管道 `VoiceBall_SingleInstance`（**不占端口**）。
> **第 2 个进程在起窗口和加载模型之前就退出了** —— 不会造成两份 CUDA 上下文。

## 七、怎么关掉这份运行时日志

| 想关什么 | 怎么做 |
| --- | --- |
| **本文（`docs/runtime-log.md`）** | **直接停更或删掉** —— 程序不读它 |
| **机器日志（`logs\voice_ball.log`）** | 🔴 **没有配置开关** —— 要改 `setup_logging()` 里的 handler。<br>（**不建议**：这个项目历史上吃过"`pythonw` 下 stdout 全丢、失败完全无声"的亏） |
| **热键看门狗** | 没有开关。**它只读按键状态，不拦触发** —— 占用可忽略 |
