# 数据

## 〇、为什么**不建** `data/`

> **本项目不建 `data\{input,output,store,cache,logs}\`。**

**理由**：它**已经有三个语义清晰的运行时数据目录** —— `audio_temp\` · `transcripts\` · `logs\` ——
**而且代码用 `__file__` 相对路径指着它们**：

```python
AUDIO_DIR      = os.path.join(BASE_DIR, "audio_temp")
TRANSCRIPT_DIR = os.path.join(BASE_DIR, "transcripts")
LOG_DIR        = os.path.join(BASE_DIR, "logs")
```

**再建一套 `data/{input,output,store,cache,logs}/` 会造成两个后果：**

1. **"到底哪个是真的"变模糊** —— 新来的人会以为数据该放 `data/`，而代码其实不看那里；
2. **要建就得搬** —— 搬就要改上面三行常量，**而它在跑、每天在用**。

**→ 所以本轮不建、不搬。** 这是**决定**，不是遗漏。

> **对照**：`ai-dialogue-processor` 的"五区全空"是因为**数据本来就在项目外**；
> **本项目是另一种情形 —— 数据就在项目内，但已经有了自己的名字。**

## 三、删除后果

| 删什么 | 后果 | 可接受吗 |
| --- | --- | --- |
| **`transcripts\`（4,367 条 / 1.81 MB）** | 🔴 **用户每天说的话的文本版，永久丢失** | ❌ **已在 `_rollback` 里单独备了一份，标"永久保留"** |
| **`audio_temp\`（5.15 GB）** | 🟠 **原始录音丢失** —— 但**转写文本还在** | ⚠️ **【用户决定】** —— 见下 |
| `logs\voice_ball.log.1`（2 MB） | 旧日志丢失 | ✅ 可接受 |
| `models\`（3.08 GB，两个） | 可重新下载（README 明说） | ✅ 可接受（**但见 [deps.md](deps.md) 的副本问题**） |
| `config.json` | `ball_pos`（球的位置）要重调 | 🟠 已备份 |

### 🟠 `audio_temp` 那 **5.15 GB** —— **这是最需要用户拍板的一件事**

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| **A** | **全留** | 继续涨（一年约 44 GB） |
| **B** | **全删** | **原始录音没了**（转写文本还在） |
| **C** | **保留最近 N 天**（如 30 天），旧的删 | **需要一个定期动作 —— 而项目里现在没有任何自动清理机制，加一个就是加功能** |

**→ 已列进 [log.md](log.md) 的未解决。本轮不动。**

### ⚠️ 一个与 `VideoKnowledgeBase` 的重要区别

| | `VideoKnowledgeBase` | **`voice_tool`** |
| --- | --- | --- |
| 用户数据 | **4.63 GB 的人生反思录像** | **5.15 GB 的日常录音 + 1.81 MB 转写文本** |
| **内容有副本吗** | ❌ **录像独一份** | ✅ **文本版在 `transcripts\`** |

**→ 删 `audio_temp` 丢的是"声音"，不是"信息"。**
**但这不等于可以随便删 —— 那是他的声音。决定权在他。**

## 五、凭据

**本项目没有凭据。**

- **没有 `.env`**
- **`config.json` 里没有密钥**（只有模型档位、热键、球位置、麦克风设备）
- **代码里零 API Key** —— 因为**全部推理都在本机**（faster-whisper + CUDA，不调任何云服务）

**→ PLAYBOOK 步骤 6 的「凭据怎么处理」两条分支，本项目都不适用。**
**`docs\deps.md` 里写了一句结论：「本项目无凭据，音频与文本都不出机器」。**
