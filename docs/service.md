# 服务

## 一、结论：**没有常驻服务**

`services.yaml` 写的是 `services: []`。

- **不监听任何端口**
- **不自启服务**（**但有一个开机自启项，见第三节 —— 那是两回事**）

## 二、⚠️ 但有一个**常驻进程**（不是服务）

| | |
| --- | --- |
| **是什么** | **悬浮球本体** —— `voice_ball.py` 跑在 `pythonw.exe` 里 |
| **怎么起** | 双击 `启动语音悬浮球.bat`，**或开机自启** |
| **活多久** | **一直活着**（直到用户从托盘退出） |
| **干什么** | 画那个球、监听全局热键、等用户点 |
| **监听端口吗** | ❌ **不监听** |

### 单实例机制

**用 `QLocalServer` / `QLocalSocket`**（**命名管道，不是端口**），名字 `VoiceBall_SingleInstance`。

**代码里的理由**（`voice_ball.py` L1585）：

> 没有它的时候：**开机自启动 + 手动点 bat 会叠出两个悬浮球** ——
> 两份 CUDA 上下文、两个全局热键监听、两份 1.5GB 模型。**用户看到的就是"桌面上启动了两个"。**

**→ 这段话同时证明了两件事**：① 自启确实在使用中；② 单实例机制是为此加的。

### ⚠️ 失效模式：**静默**

**值是绝对路径。搬动项目 → 开机时 Windows 去执行那个路径 → 不存在 → 什么都不发生。**

- **不报错**
- **不弹框**
- **没有任何提示**

**用户只会觉得"今天怎么没看见球"。**

> **对照 `markdown-reader`**：它的右键菜单失效（ProgID + `command` 值也是绝对路径）**是响亮的** ——
> 点下去会报"找不到文件"。**而这一条，你根本不会知道它失效了。**
>
> **→ PLANBOOK「已知的坑」第 15 条记了这个区别。**

**自愈**：在新位置跑一次程序 → 重新 `set_autostart(True)`；或手工改注册表那个值。

> ⚠️ **本轮整理没有碰注册表**（只做了只读查询），**也没有搬动项目** → **自启项仍然正确。**

## 六、🔵 顺带发现（**方案外，已报备**）

**查 `HKCU\...\Run` 时，同一个键下还看到 `MyWorkbench` 这一条：**

```
MyWorkbench = D:\MyProject\Workbench\src-tauri\target\release\my-workbench.exe
```

**→ 那是 `Workbench` 项目**（系统级悬浮工具栏，`project_manager\MAP.md` 里列为「未整理」）。

**两点值得记：**

1. **`Workbench` 也有开机自启** —— 它还没整理，这一条留给它那一轮；
2. 🔴 **它的自启指向 `src-tauri\target\release\`** —— 也就是**运行中的 exe 住在构建产物目录里**。
   **这和 `Note` 是同一个形态**（`Note` 也跑在 `src-tauri\target\release\my-workbench-notes.exe`）。
   **→ 意味着：删 `target\` 会直接杀掉一个开机自启的程序。**

**本轮没有动它**（不在授权范围）。已记进 `project_manager\docs\log.md`。
