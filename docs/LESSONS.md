## 二·补、2026-10-04 ~ 10-09 新增的（【站】，全部用实测数据钉住）

> **这一段是"整理"之外的一轮真实修复留下的。** 每一条都**先证伪、再改、再双向验证**。

| # | 结论 | 怎么验的 |
| --- | --- | --- |
| **27** | 🔴 **API 说"打开成功"不等于它给了你音频。** WASAPI 单声道能正常 `open`、电平也正常（峰值 955 / 标准差 128），**但全是高频垃圾**（过零比 **0.178** vs 健康通路 **0.084**，谱质心 2250 Hz vs 426 Hz）。**转写结果因此变成英文幻觉。** | 同一段 300 秒录音：默认参数出「Put it in the oven…」整段英文菜谱；修好后 ASCII 字母占比 **32% → 0%** |
| **28** | 🔴 **会抖的判据不能当门禁。** 一度用频谱（谱质心 / 过零比）拦死路，**但环境噪声下极不稳定** —— 同一条好通路两次量到 **0.213 / 0.098**、质心 **1761 / 1815 / 426 Hz**，**把好通路误判成"没有可用通路"**。**宁可放进一条平庸通路，也不用会抖的指标否决通路。** | 隔离测试同一通路重复测量；日志里出现过连续 4 次误杀 MME 通路 |
| **29** | 🔴 **提示词会被模型当成答案吐出来。** 为了让长音频带标点加了 `initial_prompt`，**结果 2 秒短录音的输出直接变成"请加上标点符号。"**，正确内容整段丢失。**锦上添花的功能不能拿正确性去换。** | 5 条真实录音对照：2 条短录音被提示词顶掉 |
| **30** | 🔴 **门禁不能挂在【触发路径】上。** 热键误触发的修法第一版是"触发时回查物理按键"，**结果把正常快速按键也挡掉了**（用户：「要点很多很多次」）。根因：pynput 是「钩子收事件 → 队列 → 再回调」，**回调执行时键早已松开**。**改成后台每 0.3s 对账（完全不碰触发路径）后两个方向都成立。** | 双向判据：A 没按的键被清掉 ✓ / B 真按着的键不被清掉 ✓ |
| **31** | 🔴 **"验证了一个方向"不等于"验证了"。** 第 30 条那一版**只测了"能拦住误触发"，没测"不误伤正常按键"** —— 于是修坏了。**两个方向的判据必须同时写下来。** | 本条是自我推翻，代价是一轮返工 |
| **32** | 🔴 **并发调 `Pa_Initialize` 会 native 崩溃。** GUI 线程（建菜单时）和后台探测线程**同时 `pyaudio.PyAudio()` → 访问冲突 `0xc0000005`**，进程直接死，**日志里连 Python 异常都没有**。 | `PYTHONFAULTHANDLER=1` 抓出两个线程的调用栈；`Windows 事件日志`确认 faulting module = `_portaudio.cpyd` |
| **33** | 🔴 **Whisper 在长音频上有一套固定的失效模式。** `condition_on_previous_text`（库默认**开**）把上一段输出当提示喂回去 → 长音频**复读 / 漂移 / 串词**；`temperature` 默认带回退 → **同一条音频两次结果不同**。 | 300 秒实录：默认 **643 字 / 复读 ×24**；关掉后 **135 字 / 复读 ×2**，耗时 **14.9s → 2.8s** |
| **34** | ⚠️ **"按下停止"和"停止工作"要分开。** 尾音收取（0.6s）和模型加载（3.8s）**都藏在界面之外** —— 点下去界面立刻切走。**"跟手"是设计出来的，不是天然的。** | 日志实测：收到停止请求 → 录音结束，差 **697 / 710 / 697 ms**；界面不等它 |
